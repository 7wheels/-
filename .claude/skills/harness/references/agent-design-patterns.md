# 에이전트 팀 설계 패턴

## 실행 모드

### 에이전트 팀 (기본)
팀원끼리 직접 대화·도전·검증 가능. `TeamCreate` + `SendMessage` 활용.
- 리더가 팀원 조율
- 팀원 간 직접 메시지 교환
- 공유 태스크 리스트로 진행 상황 공유

### 서브 에이전트
메인 에이전트가 서브에이전트를 생성하고 결과만 수신. 에이전트 간 소통 없음.
- 독립적 병렬 작업에 적합
- 단순 수집/처리 작업

**원칙: 기본적으로 모든 복합 패턴에 에이전트 팀을 사용한다.**

---

## 6가지 아키텍처 패턴

### 1. Pipeline (파이프라인)
순차 의존 단계. 각 단계의 출력이 다음 단계의 입력.

```
단계1 → 단계2 → 단계3 → 최종 산출물
```

**적합한 경우:** 콘텐츠 제작, 데이터 변환, 보고서 생성

### 2. Fan-out/Fan-in (팬아웃/팬인)
병렬 전문가 분석 → 통합. 에이전트 팀의 가장 자연스러운 패턴.

```
         ┌→ 전문가A ─┐
입력 ─→ ─┼→ 전문가B ─┼→ 통합 → 출력
         └→ 전문가C ─┘
```

**적합한 경우:** 리서치, 다각도 분석, 종합 평가

### 3. Expert Pool (전문가 풀)
입력 유형에 따라 적절한 전문가에게 동적 라우팅.

```
입력 → 라우터 → [전문가A | 전문가B | 전문가C] → 출력
```

**적합한 경우:** 고객 문의 처리, 코드 리뷰, 다분야 컨설팅

### 4. Producer-Reviewer (생성-검증)
생성과 검증의 반복 사이클. 최대 2-3회 반복.

```
생성자 → 검토자 → PASS/FIX/REDO → (반복)
```

**적합한 경우:** 콘텐츠 품질 관리, 코드 리뷰, 문서 작성

### 5. Supervisor (슈퍼바이저)
중앙 조율자가 작업자에게 동적으로 배분.

```
슈퍼바이저 → [작업자1, 작업자2, ...] → 결과 수집
```

**적합한 경우:** 대규모 마이그레이션, 배치 처리, 동적 작업량

### 6. Hierarchical Delegation (계층적 위임)
재귀적 하위 위임. 최대 2-3단계.

```
리드 → 팀리드A → [전문가1, 전문가2]
     → 팀리드B → [전문가3, 전문가4]
```

**적합한 경우:** 풀스택 개발, 복잡한 프로젝트, 대규모 팀

## 에이전트 정의 표준

`.claude/agents/{name}.md` 파일에 다음 섹션 포함:

```markdown
---
name: {에이전트명}
description: "{역할 + 트리거 조건}"
model: opus
---

## 핵심 역할
## 운영 원칙
## 입출력 프로토콜
## 팀 커뮤니케이션 (팀 모드만)
## 에러 처리
```

**내장 에이전트 유형:** `general-purpose`, `Explore` (읽기 전용), `Plan` (설계 전용)
