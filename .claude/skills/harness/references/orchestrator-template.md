# 오케스트레이터 스킬 템플릿

오케스트레이터는 개별 에이전트를 하나의 통합 워크플로우로 연결하는 특수한 스킬이다.

## 템플릿 A: 에이전트 팀 모드 (권장)

```markdown
---
name: {domain}-orchestrator
description: "{도메인} 관련 복합 작업 오케스트레이션. '{도메인} 전체 실행', '처음부터 다시', '결과 개선', '보완해줘' 등 요청 시 사용."
model: opus
---

# {도메인} 오케스트레이터

실행 모드: **에이전트 팀**

## Phase 0: 컨텍스트 확인

_workspace/{도메인}/ 디렉토리 확인:
- 비어있음 → 초기 실행
- 부분 완료 → 이어서 실행
- 완료됨 → 재실행/개선 모드

## Phase 1: 준비

1. 입력 분석
2. `_workspace/{도메인}/` 디렉토리 생성
3. 작업 계획 수립

## Phase 2: 팀 구성

TeamCreate로 팀 생성:
- {에이전트1}: {역할}
- {에이전트2}: {역할}
- {에이전트3}: {역할}

TaskCreate로 초기 작업 등록.

## Phase 3: 팀 실행

팀원들이 자율 협력하며 작업 수행.
리더는 TaskUpdate로 진행 상황 모니터링.
블로킹 이슈 발생 시 개입.

## Phase 4: 통합

모든 팀원 완료 확인 후:
1. `_workspace/{도메인}/` 에서 산출물 수집
2. 통합 및 후처리
3. 최종 보고서 생성

## Phase 5: 정리

팀 해산 및 리소스 정리.

## 에러 처리

| 상황 | 대응 |
|------|------|
| 에이전트 응답 없음 | 1회 재시도 후 건너뜀 |
| 파일 접근 오류 | 대체 경로 시도 |
| 품질 기준 미달 | Producer-Reviewer 사이클 추가 |
```

---

## 템플릿 B: 서브 에이전트 모드

독립적 병렬 작업에 사용. 에이전트 간 소통 없음.

```markdown
실행 모드: **서브 에이전트**

각 작업을 Agent 도구로 독립 실행:
- Agent(model="opus", task="{작업1}")
- Agent(model="opus", task="{작업2}")

결과를 수집하여 통합.
```

---

## 템플릿 C: 하이브리드 모드

Phase별로 모드를 혼용:
- 수집 Phase → 서브 에이전트 (독립 병렬)
- 분석 Phase → 에이전트 팀 (상호 검증)
- 통합 Phase → 오케스트레이터 단독

---

## 작성 원칙

1. 실행 모드를 상단에 명시
2. Phase 간 의존성 명확히 기술
3. 절대 파일 경로 사용 (상대 경로 금지)
4. 에러 핸들링 매트릭스 포함
5. description에 후속 키워드 포함: "재실행", "수정", "보완", "결과 개선"
