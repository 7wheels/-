# Harness — Agent Team & Skill Architect

도메인 특화 에이전트 팀과 지원 스킬을 설계·생성하는 메타 스킬. 하네스는 정적 산출물이 아닌 피드백을 통해 진화하는 살아있는 시스템이다.

## 핵심 원칙

1. **에이전트 정의는 파일로** — 모든 에이전트는 `.claude/agents/{name}.md`에 존재해야 하며, 도구 호출에 임베드 금지
2. **에이전트 팀이 기본** — 2인 이상 협업 시 `TeamCreate` 사용; 독립 병렬 작업에만 서브에이전트 허용
3. **Opus 모델 필수** — 모든 `Agent` 도구 호출에 `model: "opus"` 명시
4. **CLAUDE.md는 포인터 레지스트리** — 트리거 규칙 + 변경 이력만 기록; 실제 구조는 파일시스템이 담당
5. **Progressive Disclosure** — 스킬은 3단계 로딩: 메타데이터(항상), 본문(트리거 시), 레퍼런스(온디맨드)

## Phase 0: 현재 상태 감사

실행 전 반드시 현재 상태를 확인한다:

```
기존 .claude/agents/ 파일 확인
기존 .claude/skills/ 구조 확인
CLAUDE.md 내 하네스 등록 여부 확인
_workspace/ 산출물 존재 여부 확인
```

**분기 결정:**
- 신규 빌드 → Phase 1-6 전체 실행
- 기존 확장 → 필요한 Phase만 선택 실행
- 운영/유지보수 → Phase 7-5 워크플로우

## Phase 1: 도메인 분석

사용자 요청에서 다음을 추출한다:

1. **핵심 도메인** — 어떤 분야/문제를 다루는가
2. **주요 작업 카테고리** — 어떤 유형의 작업들이 반복되는가
3. **입출력 패턴** — 무엇이 들어오고 무엇이 나가는가
4. **품질 기준** — 어떤 결과가 좋은 결과인가
5. **협업 필요성** — 에이전트 간 소통이 필요한가

## Phase 2: 팀 아키텍처 설계

### 실행 모드 선택

| 모드 | 적합한 경우 |
|------|------------|
| 에이전트 팀 | 2인 이상 협업, 결과물 상호 검증 필요 |
| 서브 에이전트 | 독립적 병렬 작업, 단순 수집/처리 |
| 하이브리드 | Phase별 모드 혼용 |

### 패턴 선택 → [agent-design-patterns.md](references/agent-design-patterns.md) 참조

- **Pipeline** — 순차 의존 단계
- **Fan-out/Fan-in** — 병렬 전문가 분석 → 통합
- **Expert Pool** — 입력 유형별 전문가 라우팅
- **Producer-Reviewer** — 생성-검증 사이클
- **Supervisor** — 중앙 동적 배분
- **Hierarchical Delegation** — 재귀적 하위 위임

## Phase 3: 에이전트 정의 생성

각 에이전트마다 `.claude/agents/{name}.md` 파일 생성:

```markdown
---
name: {에이전트명}
description: "{트리거 조건을 포함한 상세 역할 설명}"
model: opus
---

# {에이전트 제목}

## 핵심 역할
[에이전트의 주된 책임]

## 운영 원칙
[작업 방식, 우선순위, 제약사항]

## 입출력 프로토콜
- 입력: [받는 데이터 형식]
- 출력: [생성하는 데이터 형식]
- 저장 경로: [_workspace/{경로}]

## 팀 커뮤니케이션 (팀 모드만)
- 수신: [{에이전트명}으로부터 {메시지 유형}]
- 발신: [{에이전트명}에게 {메시지 유형}]

## 에러 처리
[실패 시 행동 방침]
```

## Phase 4: 스킬 생성

각 스킬은 500줄 이내로 유지; 초과분은 `references/`로 이동.

스킬 작성 상세 기준 → [skill-writing-guide.md](references/skill-writing-guide.md)

### Description 작성 원칙
- 트리거 상황을 구체적으로 기술
- 유사하지만 트리거하면 안 되는 케이스 경계 명시
- 약간 "pushy"하게 — Claude의 보수적 판단을 보상

## Phase 5: 통합 및 오케스트레이션

오케스트레이터는 특수한 형태의 스킬 → [orchestrator-template.md](references/orchestrator-template.md) 참조

### CLAUDE.md 등록 형식

```markdown
## 하네스: {도메인명}
트리거: {상황 설명}
에이전트: {에이전트 목록}
스킬: {스킬 목록}
변경 이력: {날짜} - {변경 내용}
```

## Phase 6: 검증 및 테스트

1. **구조 검증** — 모든 에이전트 파일 존재 확인
2. **트리거 검증** — Should/Should-NOT 케이스 테스트
3. **실행 검증** — 스킬 없이 vs. 스킬 있이 비교
4. **팀 통신 검증** — 메시지 플로우 확인
5. **산출물 검증** — 기대 출력 형식 확인
6. **에러 처리 검증** — 실패 시나리오 테스트

## Phase 7: 하네스 진화

피드백 기반 지속 개선:
- 사용자 피드백 → 원리 수준 일반화 (오버피팅 금지)
- 운영 이력 → `_workspace/release/` 에 기록
- 스킬 효과 측정 → grading.json 스키마 활용

## 최종 산출물 체크리스트

- [ ] `.claude/agents/{name}.md` 파일 생성 완료
- [ ] `.claude/skills/{name}/SKILL.md` 생성 완료 (500줄 이내)
- [ ] 레퍼런스 파일 `references/`에 분리
- [ ] CLAUDE.md에 하네스 포인터 등록
- [ ] 오케스트레이터 스킬 생성
- [ ] 트리거 검증 완료

## 금지 사항

생성하지 않을 것:
- `.claude/commands/` 디렉토리
- 하드코딩된 에이전트 프롬프트 (도구 호출 내)
- 트리거 키워드 없는 스킬 description
- 구조 상세 목록이 담긴 CLAUDE.md
